# Предметы

Предмет — это ресурс Godot (`Resource`). Каждый предмет существует в виде отдельного файла `.tres`, настраивается в инспекторе и подключается к сценам напрямую. Код не создаёт предметы через `new` и не хранит их список: единственный источник данных — каталог ресурсов.

## Состав системы

| Файл | Назначение |
| --- | --- |
| `Game/Item/Item.cs` | Базовый класс `Item`: общие поля и метод `Use`. |
| `Game/Item/ItemCatalog.cs` | Ресурс-каталог со списком всех предметов. |
| `Game/Item/ItemDatabase.cs` | Статический реестр: загружает каталог и ищет предметы по ID. |
| `Objects/Items/ItemCatalog.tres` | Единственный экземпляр каталога, который читает `ItemDatabase`. |
| `Objects/Items/**` | Ресурсы предметов, сгруппированные по категориям. |
| `Game/Item/PickUp/PickUp.cs` | Предмет на земле. Ссылка на ресурс задаётся в инспекторе. |

## Поля предмета

| Поле | Тип | Назначение |
| --- | --- | --- |
| `Id` | `int` | Уникальный числовой идентификатор. |
| `Name` | `string` | Название для игрока. |
| `Icon` | `Texture2D` | Иконка для инвентаря и предмета на земле. |
| `Description` | `string` | Описание. |
| `MaxStack` | `int` | Максимум в одном слоте. `1` — не стакается. |

Наследники добавляют свои поля. Например, `HealingPotion` и `ChickenMeat` имеют `HealAmount` — сколько здоровья восстанавливает предмет.

## Идентификаторы

`Id` — положительное целое число, уникальное в пределах каталога. Идентификатор используется в диалогах и сейвах, поэтому он является частью формата данных:

- значение не меняется после того, как предмет попал в сейв или диалог;
- освободившийся ID не передаётся другому предмету;
- новый предмет получает следующий свободный номер.

Текущие значения: `1` — пустой предмет, `2` — зелье лечения, `3` — куриное мясо.

## Создание предмета

1. Выбрать поведение. Если подходит существующая логика, используется готовый класс. Для новой логики создаётся наследник `Item` (см. ниже).
2. Создать ресурс в папке категории `Objects/Items/<Категория>/`: **Create New → Resource**, затем выбрать класс предмета (`HealingPotion`, `ChickenMeat` и т.п.).
3. Заполнить `Id`, `Name`, `Icon`, `Description`, `MaxStack` и поля наследника.
4. Добавить ресурс в массив `Items` каталога `Objects/Items/ItemCatalog.tres`.
5. Использовать ресурс в сценах.

После добавления в каталог предмет доступен через `ItemDatabase` по ID. Перекомпиляция и правка кода не нужны.

## Новый тип предмета

```csharp
using Godot;

[GlobalClass]
public partial class Key : Item
{
    [Export] public string DoorId { get; set; } = "";

    public override bool Use(Node2D user)
    {
        // Логика использования ключа.
        return false;
    }
}
```

Атрибут `[GlobalClass]` делает класс доступным в редакторе при создании ресурса. Метод `Use` вызывается из `Inventory.UseItem`; возврат `true` означает, что предмет использован и его количество уменьшается.

## Использование в сценах

Предметы подключаются как обычные ресурсы:

- `PickUp.Item` — предмет, лежащий на земле;
- `Chest.Loot` — список предметов в контейнере;
- любой `[Export] Item` на компоненте или ресурсе.

Ссылка в инспекторе не зависит от `Id`: `Id` нужен только там, где предмет описывается данными (диалоги, сейвы).

## Предметы на земле

`PickUp` — это `Area2D` с экспортируемыми `Item` и `Count`. Количество показывается при наведении. Если игрок подбирает стак, а в инвентаре не хватает места, на земле остаётся остаток.

Предмет можно создать в сцене вручную или из кода:

```csharp
var pickup = new PickUp();
pickup.Init(item, count);
player.GetParent().AddChild(pickup);
pickup.GlobalPosition = player.GlobalPosition;
```

`Init(item, count)` задаёт предмет и количество до добавления узла в дерево. Выброс из инвентаря построен на этом же методе.

## Использование в коде

```csharp
Item potion = ItemDatabase.Get(2);

if (ItemDatabase.TryGet(3, out var meat))
{
    player.Inventory.AddItem(meat, 2);
}

foreach (Item item in ItemDatabase.All)
{
    GD.Print(item.Id, item.Name);
}
```

`ItemDatabase` загружает `res://Objects/Items/ItemCatalog.tres` при первом обращении. Если каталог или ID не найдены, в консоль выводится ошибка. Метод `Reload` перечитывает каталог и применяется только при изменении ресурсов во время выполнения.

В коде предпочтительна прямая ссылка на ресурс через `[Export]`. `ItemDatabase` применяется там, где есть только числовой ID: диалоги, сохранения, таблицы лута в данных.

## Диалоги

В JSON диалога предмет указывается числовым ID:

```json
{ "type": "item", "arg": 2, "value": 1 }
```

Для условий используется то же значение:

```json
{ "type": "item", "key": "2", "op": ">=", "value": 1 }
```

`arg` и `key` можно записать строкой (`"2"`) или числом (`2`) — результат одинаковый.

## Диагностика

| Сообщение | Причина |
| --- | --- |
| `не удалось загрузить каталог ...` | Не найден `Objects/Items/ItemCatalog.tres` или он не является `ItemCatalog`. |
| `не задан положительный Id` | У ресурса `Id` равен `0` или отрицательный. |
| `ID ... занят предметами ...` | Два ресурса используют один `Id`. |
| `предмет с ID ... не найден` | ID отсутствует в каталоге. |
| `PickUp создан без Item` | В сцене не назначен ресурс предмета. |

## Почему не конструкторы и не статические ссылки

Ресурсный подход выбран как единственный способ описания предметов:

- предмет настраивается в инспекторе, а не в конструкторе класса;
- сцены ссылаются на ресурс напрямую, без промежуточного кода;
- новый предмет не требует перекомпиляции;
- каталог задаёт один источник истины для ID.

Статические поля с ресурсами потребовали бы жёстко прописанных путей `res://`, загрузки ресурсов на этапе инициализации статического класса и правки кода при каждом новом предмете.
